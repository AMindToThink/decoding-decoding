# Reproduction Guide

Written so someone with no access to the original machine (`cs29824`) can
rebuild the environment, get the data, and re-run the experiments and paper
build. Every command below is copied or adapted from a real docstring/config
in this repo; sections marked `TODO (Matthew)` are things that could not be
verified from repo contents alone.

## 1. Environment

- Python: **3.11** (`pyproject.toml` `requires-python = ">=3.11"`, and
  `.python-version` pins `3.11` exactly).
- Dependency manager: **uv** (`pyproject.toml` + `uv.lock` are both present
  and checked in).

```bash
# from the repo root
uv sync
```

This installs, per `pyproject.toml`: `datasets`, `matplotlib`, `numpy<2.3`,
`polars`, `pyarrow`, `scipy`, `torch==2.9.1`, `tqdm`, `vllm==0.15.1`, plus the
`dev` group (`pytest`). `torch`/`torchvision`/`torchaudio` are pinned to the
`pytorch-cu128` wheel index (see `[[tool.uv.index]]` in `pyproject.toml`):

> Pin torch to the cu128 wheel: the system driver (575.51.03 / CUDA 12.9) on
> the original machine was too old for the default cu130 wheel that uv
> resolves for newer torch. If your GPU driver supports a newer CUDA runtime
> you may not need this pin, but changing it is untested here.

Run the test suite (CPU-only tests run by default; GPU tests are gated, see
§4):

```bash
uv run pytest
```

## 2. Data

No dataset is vendored in the repo (data-loading code fetches from the
Hugging Face Hub at run time via `datasets.load_dataset`, either directly or
through `decoding_decoding.natural_text_filter`). All datasets found by
grepping the codebase for `load_dataset(...)`:

| Dataset (HF id) | Config / split | Used by | Purpose |
|---|---|---|---|
| `Salesforce/wikitext` | config `wikitext-103-raw-v1`, splits `validation`+`test` | `src/decoding_decoding/natural_text_filter.py::load_wikitext_passages` | "WikiText-103" corpus arm |
| `euclaise/writingprompts` | split `test` | `src/decoding_decoding/natural_text_filter.py::load_writingprompts_passages` | "WritingPrompts" corpus arm |
| `wikimedia/wikipedia` | configs `20231101.yo` (Yoruba), `20231101.eo` (Esperanto), `20231101.te` (Telugu) | `scripts/run_self_calibration.py` (`_WIKI_LANG`, streaming) | low-resource-language survey arms |
| `sedthh/gutenberg_english` | field `TEXT` | `scripts/run_self_calibration.py` (streaming) | "gutenberg" survey arm |
| `sander-wood/irishman` | field `abc notation` | `scripts/run_self_calibration.py` (streaming) | "abc_music" survey arm |

`scripts/run_self_calibration.py --part survey` also uses two *synthetic*,
non-HF arms generated in-process (`recaman`: a deterministic Recamán-sequence
digit stream; `shuffled_wikitext`: WikiText passages with tokens permuted) —
no download needed for those.

All of these are public HF datasets; no `HF_TOKEN` requirement was found in
the code, but set one (`huggingface-cli login` or `export HF_TOKEN=...`) if
you hit rate limits — see §4.

**Committed vs. regenerated data:** `.gitignore` excludes `results/` entirely
and several large raw-artifact subdirectories of `data/` (`data/logprobs/`,
`data/traces/`, `data/counter_decode/`, `data/counter_decode_sigma_sweep/`,
`data/counter_decode_extreme/`, `data/counter_decode_tight_prior/`,
`data/counter_decode_priors/`, `data/counter_decode_fuzzy/`,
`data/counter_decode_entropy_stability/`, `data/counter_decode_shape/`,
`data/natural_text_filter/`, plus `data/run_metadata*.parquet`,
`data/manifest.parquet`, `data/config.json`, `data/logs/`). Everything else
under `data/` and the 86 files under `results/` that predate those `.gitignore`
rules **are** checked into git (e.g. `data/counter_decode_belief_sweep/`,
`data/calibration_baseline/`, `results/counter_decode/*/summary.json`,
figures, `findings.tex`). Run `git ls-files data results` to see exactly
what's tracked. Anything gitignored must be regenerated by re-running the
relevant script in §3.

## 3. Running

Model weights (Hugging Face, downloaded automatically on first use, no auth
token required for these public checkpoints):

- `Qwen/Qwen2.5-3B` — the primary model used throughout (`MODEL_NAME` in
  `src/decoding_decoding/generate.py`, `natural_text_filter.py`,
  `counter_decode_generate.py`).
- `gpt2-large` — secondary model, used only in the full-sequence go/no-go
  script (`scripts/run_full_sequence_go_no_go.py`).
- `sshleifer/tiny-gpt2` — test-only stand-in (`tests/test_counter_decode_generate.py`).

The paper's three headline results (see `paper/writeup.tex` abstract) map to
these entry points. All scripts are run with `uv run python scripts/<name>.py`
and each script's own module docstring contains an authoritative usage
example; the ones below are quoted directly from those docstrings.

**(1) Decoder tracking (top-k / blacklist):**
```bash
uv run python scripts/run_experiment.py [--max-tokens N] [--out-dir DIR]
# 32 prompts x {1,3,5,inf} top-k conditions x 8 runs at L=1024 on Qwen2.5-3B
# -> data/run_metadata.parquet + per-sequence .npz logprobs

uv run python scripts/run_blacklist_experiment.py
uv run python scripts/analyze_blacklist.py
```

**(2) Streaming inverse-temperature estimator / self-calibration:**
```bash
CUDA_VISIBLE_DEVICES=0 uv run python scripts/run_self_calibration.py \
    --part recovery --temps 0.5 0.7 1.0 1.5 2.0 --n-seq 64
# -> data/self_calibration/recovery.npz,
#    results/counter_decode/self_calibration/recovery.json

uv run python scripts/run_calibration_baseline.py     # Exp A: streaming vs batch MLE beta-hat
uv run python scripts/run_natural_text_filter.py       # streaming filter on natural text
```

**(3) Grid-mixture certificate (Vovk Aggregating Algorithm):**
```bash
uv run scripts/grid_certificate_experiments.py synthetic   # H1 + H3 (CPU)
uv run scripts/grid_certificate_experiments.py model       # H2 + H4 (needs GPU, Qwen2.5-3B)
uv run scripts/grid_certificate_experiments.py analyze     # tests + results.json
uv run scripts/grid_certificate_experiments.py all
uv run python scripts/build_grid_certificate_table.py
```

**Other experiment families in `scripts/`** (counter-decoding sweeps,
entropy-probe, full-sequence structured-twist go/no-go, etc.) each begin with
a `"""..."""` module docstring giving the exact `uv run` invocation and GPU
env var — e.g. `scripts/run_counter_decode.py`, `scripts/run_entropy_probe.py`,
`scripts/run_full_sequence_go_no_go.py` (`--model gpt2-large` or
`--model Qwen/Qwen2.5-3B`). Read the top of a script before running it rather
than guessing flags.

**Turning raw results into the paper's numbers/tables** (numbers-from-scripts
discipline — see `scripts/build_paper_macros.py` docstring):
```bash
uv run python scripts/build_paper_macros.py          # -> results/tables/paper_macros.tex, tab_*.tex
uv run python scripts/build_calibration_baseline_macros.py
uv run python scripts/build_natural_text_macros.py
uv run python scripts/build_self_calibration_macros.py
uv run python scripts/build_survey_macros.py
uv run python scripts/build_full_sequence_macros.py
uv run python scripts/build_bib.py                    # paper/refs.bib from paper/refs_ids.toml
```

**Building the paper PDF** (requires a LaTeX toolchain — `latexmk`/`pdflatex`,
TeX Live; not managed by uv). Two paper documents exist:
`paper/writeup.tex` (title "Knowing One's Self is Wisdom...", the version
whose abstract matches `paper/refs.bib`/current framing and that self-links
to this GitHub repo) and `paper/decoding_paper.tex` (earlier "tech report"
draft, title "Modeling and Calibrating: LLMs Figure out their Decoding
Process"). There's also `paper/talk.tex` (slides).

```bash
cd paper
latexmk -pdf writeup.tex
# or: latexmk -pdf decoding_paper.tex
```

## 4. External dependencies

- **Hugging Face Hub**: model weights (`Qwen/Qwen2.5-3B`, `gpt2-large`,
  `sshleifer/tiny-gpt2`) and all datasets in §2 are pulled from the Hub at
  run time. No `HF_TOKEN` env var reference was found in the code, so these
  are presumably accessed anonymously; set `HF_TOKEN` if you need higher
  rate limits or hit gated-repo errors.
- **No experiment tracker**: no `wandb` (or similar) import anywhere in
  `src/`, `scripts/`, or `tests/` — nothing to configure there.
- **No API keys found** in the codebase (no `os.environ`/`getenv` reads for
  any secret besides GPU selection below).
- **Environment variables used by the code:**
  - `CUDA_VISIBLE_DEVICES` — GPU selection; every GPU-touching script sets
    or defaults this (usually `"0"`). Multi-GPU sweeps are launched by
    running the same script twice with `CUDA_VISIBLE_DEVICES=0` /
    `CUDA_VISIBLE_DEVICES=1` in parallel (see e.g.
    `scripts/run_entropy_stability_sweep.py` docstring).
  - `RUN_VLLM_SMOKE=1` — opt-in gate for `tests/test_generate_smoke.py`.
  - `DD_GPU_TESTS=1` — opt-in gate for `tests/test_counter_decode_generate.py`.
- **No sibling/local repos** are imported — `pyproject.toml` has no path or
  git dependencies; everything under `src/decoding_decoding/` is this
  package itself (installed in editable mode by `uv sync` via the
  hatchling build backend).
- **LaTeX toolchain** (`latexmk`, `pdflatex`, TeX Live) is required to build
  `paper/*.pdf` but is not a Python/uv dependency — install separately (e.g.
  system package manager or TeX Live distribution).

## 5. Hardware

- Generation/inference scripts require an NVIDIA GPU with CUDA. Evidence in
  code:
  - `scripts/grid_certificate_experiments.py`: `run_model()` raises
    `RuntimeError("model experiments need a GPU (prereg: Qwen2.5-3B)")` if
    `torch.cuda.is_available()` is false. The `synthetic` and `analyze`
    subcommands are CPU-only.
  - `src/decoding_decoding/generate.py` uses vLLM with
    `tensor_parallel_size=1`, `gpu_memory_utilization=0.85` (single GPU).
  - `tests/test_generate_smoke.py` docstring: the vLLM smoke test "loads
    ~6 GB of weights" (Qwen2.5-3B).
  - `CUDA_VISIBLE_DEVICES` is pinned to a single device (`"0"` by default)
    throughout — no multi-GPU tensor/data parallelism is implemented; the
    handful of sweep scripts that mention GPU 1 just run a second, entirely
    separate process pinned to `CUDA_VISIBLE_DEVICES=1`.
  - `scripts/run_full_sequence_go_no_go.py` uses `torch.float32` for
    `gpt2-large` and `torch.bfloat16` for Qwen2.5-3B.
- No explicit minimum-VRAM number is stated anywhere in the repo.
